# design-compare Skill（デザイン案の比較モックを出して選んでもらう）

> **Core Principle**: 案は言葉で説明するより、**差が見える 1 枚のモックに並べて選んでもらう**。
> 完璧な再現は不要 — 「この差でどれがいいか」を判断できる最小のモックでよい。
> 作り込みに時間をかけず、案出しの一部として素早く出す。

## いつ使うか

- デザイン・スタイルの変更案を 2 つ以上出すとき（ユーザーの明示依頼がなくても原則出す）
- README・スキルシート・設計メモなど Markdown 文書の**構成案**を 2 つ以上出すとき（セクションの分け方・見出し名・どこに何を書くか）
- 公開文書の**文言案**を 2 つ以上出すとき（見出しの言い回し、1 行の書き換え、括弧の補足の有無）。前後の行と並べて初めて重複や座りの悪さが見えるので、1 行の違いでも並べる価値がある
- 使わない場面: 案が 1 つしかないとき・ユーザーが文言を具体的に指示したとき・誤字や記法の修正
- 案が決まった後の実装の見た目確認は本スキルの範囲外。そのリポジトリの UI 確認規約（Storybook 等）に従う（比較モックはその前段の案選び専用）

## 2 つのモード

どちらも「現状を最初に置く・差を色で示す・実寸で並べる」は共通。作り込みの量だけが違う。

| | 文言モード | 構成・デザインモード |
| --- | --- | --- |
| 対象 | 1 行の書き換え・見出しの言い回し | セクションの分け方・レイアウト・スタイル |
| 雛形 | `assets/markdown-compare.html` をコピーして使う | 実物の CSS から採寸して自分で書く |
| 案の数 | 1 論点あたり 5〜8 個 | 1 論点あたり 3〜5 個 |
| 各案に添えるもの | 何を変えたか 1 行 + 実測値 | 何を変えたか 1 行 + 見た目に出ない差 |

文言モードで案を多めに出すのは、1 行の案なら読み比べる負担が小さく、選択肢が少ないと「どれも少し違う」で止まるため。構成モードで 6 個以上並べると比較しきれない。

雛形は出発点であって強制ではない。実物に寄せる必要がある案（ダーク面・独自のフォント・Web アプリの画面）は、雛形を使わず実装から採寸して書く。

## 比較ページの作り方

1. **置き場所はセッションの scratchpad**。公開物ではないのでリポジトリ内に置かない（scratchpad が無い実行環境でだけ `.tmp/design-compare/` を使う）。
   ファイル名は `design-compare-<topic>.html`
2. self-contained な単一 HTML・`lang="ja"`。外部 CDN・外部フォントは使わない
3. **実物の値を使う**。色・フォントサイズ・不透明度・余白は対象実装から読み取った実値を使い、
   表示テキストも実ページの実データを使う（ダミー文字は折り返しや密度の判断を誤らせる）
4. ページ構成:
   - 冒頭に H1 + 前提の 1 行（どのページのどの部分か・全案共通の変更があるならそれ）
   - 論点ごとにセクション（H2）を分ける
   - **必ず「現状」を最初に置く**（差のベースライン。現状タグはグレーで区別）
   - 各案 = 案ラベル（案A / 案B…）+ 何を変えたか 1 行 + モック。推し案には「推し」バッジ
   - 案は**縦に並べる**。横並びのグリッドは幅が実寸にならず、折り返し・密度の差が見えなくなる
   - 論点が複数あるときは、最後に**推し案を全部適用した「全部入りプレビュー」**を置く
   - その論点では動かさない行は、グレー（`.fixed`）にして固定であることを示す
5. モックの幅・背景・角丸は実物に合わせる（対象実装の CSS 変数・Tailwind クラスから実値を読み取り、ダーク面の案なら実際の背景色のパネルに載せる）
   - Markdown 文書の案は、その文書が読まれる場所の描画に寄せる。GitHub の README なら幅 896px・本文 16px・行間 1.5・H2 に下線、箇条書きは `padding-left: 2em`（雛形はこの値で作ってある）
6. ブラウザ依存の CSS（`word-break: auto-phrase` など）を使う案には、対応状況をバッジで明記する
7. 差分を色で示す。現状から変えた箇所は黄色の背景、削る箇所は赤の取り消し線。冒頭の前提行に凡例を 1 行書く
8. 全案に共通する長いブロックは `<template>` に 1 回だけ書き、各案の差し込み位置へ JS で複製する。案ごとに同じ本文を貼ると、修正時にずれる
9. 1 行に収まるかどうかが論点になる文書（スキルシートなど）では、各案の下に実測値を添える。**案を作る段階で毎回測らず、明らかに長い候補を落としてから、残った案をまとめて 1 回で測る**

## 雛形の使い方（文言モード）

`assets/markdown-compare.html` を scratchpad にコピーし、3 か所を置き換える。

- `<!-- TITLE -->`（2 か所）… 何を選ぶページか
- `<!-- NOTE: ... -->` … どの文書のどこか・全案に共通する前提
- `<!-- SECTIONS: ... -->` … 「現状」と各案の `<section>`（雛形のコメント内に 2 つ例がある）

CSS には GitHub 表示の枠（`.gh`）・タグ（`.tag.now` / `.tag.plan` / `.push`）・差分色（`.ch` / `.del` / `.fixed`）・実測値の行（`.w` / `.cav`）が入っている。CSS は書き足さずに済む想定だが、足りなければ `<style>` に追記してよい。

## 提示の仕方

- 比較ページは **`open` で開いてよい**（他の成果物は「パス提示のみ」が原則だが、比較ページは例外とするユーザー許可済み）。あわせてフルパスも提示する
- (Claude Code のみ) SendUserFile（display: render）でも送り、サイドパネルでも見られるようにする
- 見た目に出ない差（実装コスト・保守性・レスポンシブ対応への影響など）はチャット側の説明で補足する
- ユーザーが案を選んだら実装に進む。比較ページは使い捨てで、commit しない
