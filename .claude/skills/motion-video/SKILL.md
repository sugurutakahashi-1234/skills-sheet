# motion-video（モーショングラフィックス動画の聞き出しとテイスト）

動画は HyperFrames（HTML と GSAP で組み、ブラウザで 1 フレームずつ撮って MP4 にする）で作る。作り方・検査・途中レビューの仕組みは HyperFrames の公式スキル（`hyperframes` `hyperframes-core` `motion-graphics` など）が持っているので、ここでは重ねない。このスキルが担うのは、その手前と周りの 3 つ: 何を聞くか、テイストをどう散らすか、何をレビューに出すか。

## 前提

- 使う側のリポジトリが `heygen-com/hyperframes` のスキルを `sources` で取っている。選ぶ名前と取り込みの注意は ai-rules の README「よく使う外部 source」。入っていなければ、作り始める前にそれを伝える
- `npx hyperframes` は Node 22 以上・Chrome・ffmpeg を使う
- 使う側のリポジトリが、題材（事実の出どころにするファイル）・見本（参考動画があれば）・作業ディレクトリをルールか CLAUDE.md に書いている。このスキルは題材の中身を知らないので、書かれていなければ最初に聞く

## 聞くこと

1 回に 1 問、推す答えを先頭にした選択肢つきで聞く。題材から読めることは聞かない。

1. **見る人。** 誰に見せるか
2. **一番伝えたいこと。** 1 つに絞る。題材から候補を 3〜4 個作って選んでもらう
3. **流す場所と長さ・縦横。** 例: X の投稿なら横 16:9 で 30 秒。既定は 30 秒
4. **雰囲気。** 軸ごとの 2 択を 1 画面にまとめて聞いてよい。明るさ（明るい / 暗い）・速さ（速い / ゆったり）・硬さ（真面目 / 遊び）・主役（文字 / 図解 / 写真）
5. **避けたいテイスト。** 見本があれば「これは違う」を選んでもらう。好みを言葉で言うより、外れを選ぶ方が答えやすい
6. **音。** 自作の BGM / 無音 / 曲を持ち込む

「おまかせ」と言われた問いは推す答えで埋める。聞き終えたら答えを 1 つの要約にまとめ、答えてもらったものと推測で埋めたものを分けて見せる。

## テイストを散らす

1 行の依頼で作ると、グラデーションの背景・中央の文字・全部フェードイン・最後にロゴ、という同じ形に寄る。同じ人が作るたびに似た動画になるのも同じ原因で起きる。

- 案は `references/concepts.md` の構成 19 種 × 見た目 10 種から作る。`scripts/draw.ts` が、作業ディレクトリの `history.jsonl` にある直近の構成と見た目を避けて、種（seed）付きで 3 案を引く。2 案は雰囲気の答えに近いもの、1 案は一番遠い「大外し」
  ```bash
  bun "$SKILL_DIR/scripts/draw.ts" --history <作業ディレクトリ>/history.jsonl --brightness 明るい --speed 速い --tone 真面目 --have UI
  ```
- 引いた組み合わせを、題材に合わせた具体的な案に直して見せる。各案に 1 文の前提、見た目、構成の指紋（`構成 · 場面数 · 各場面の主役 · 始まり · 終わり`）を書く。前回と変える決まりは `references/concepts.md` の末尾
- 選ぶ・混ぜる・振り直す（別の種で引き直す）のどれでもよい。全部違うと言われたら、何が違うかを 1 問だけ聞いてから引き直す
- 書き出したら、採った案を `history.jsonl` に 1 行足す（`{"date": "...", "concept": 構成の番号, "direction": "見た目の名前", "fingerprint": "...", "title": "..."}`）
- HyperFrames は前回の答えを次回の推奨にし、承認された構成をレシピとして保存して次回に勧める。似た動画に寄るので、利用者が「前回と同じで」と言ったときだけ使う

## 途中のレビュー

HyperFrames のレビューの流れ（brief の `storyboard: yes`）に乗せる。止まる所は 4 つ。

1. 何秒に何を見せるかの表。中身の良し悪しはここで言ってもらう
2. 場面ごとの静止画スケッチ。本物の字・色・文言で描き、動きは付けない
3. 組み立てた後の静止画の一覧（1 秒に 2 枚）。厳しい演出家として採点し、直した点を報告する
4. プレビューを開き、書き出してよいか聞く

指摘された場面だけを直して出し直す。全体を作り直すと、良かった場面まで変わってしまう。

## 作るときの落とし穴

- **題材にない事実を足さない。** 数字・社名・期間・成果を作らない。動画は題材の要約で、盛ると題材そのものの信頼を落とす
- **日本語の書体はローカルのファイルを読む。** HyperFrames の検査は `@font-face` の無い書体名を落とす。Google Fonts の OFL 書体（Dela Gothic One・Zen Kaku Gothic New・JetBrains Mono など）を作業ディレクトリの `assets/fonts/` に置く
- **音と映像は同じ拍の表で組む。** 場面の切り替わり・一撃・文字の出を拍番号で書けば、音とずれない。曲を持ち込まないときは `scripts/beat-music.ts` が拍の表から BGM と効果音を合成する（HyperFrames の BGM 検索は heygen CLI が無いと使えない）
- **文字幅は canvas の `measureText` で測る。** 場面は出番の外で非表示になり、DOM で測ると幅が 0 になる
- **`letter-spacing` や `width` を動かさない。** フレーム撮影でかくつく。transform と opacity で動かす
- **書き出しは `npx hyperframes render --fps 60 --quality delivery`。** 書き出す前に `npx hyperframes check` を通す

## 置き場所

作業ディレクトリは使う側のリポジトリが決める（コミットしない場所が多い）。`history.jsonl` もそこに置く。
