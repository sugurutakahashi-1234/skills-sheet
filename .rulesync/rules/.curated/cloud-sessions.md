# クラウドの会話で作業するとき

環境変数 `CLAUDE_CODE_REMOTE` が `true` なら、手元の Mac ではなくクラウドの使い捨てのコンテナで動いている。手元と違う所だけを書く。

- **変更は PR で出す**。クラウドではハーネスが作業ブランチと PR の作り方を決めるので、リポジトリのルールが「main に直接 push」と書いていても、ブランチに push して PR を開く（push の承認は、ユーザーが PR をマージすることに置き換わる）。マージはユーザーが決める。いくつものリポジトリにまたがる作業では、最後に PR の一覧を 1 回で返し、まとめてマージしてもらう
- **手元の鍵と認証は無い**。dotenvx の鍵ファイル、gh の keyring、gcloud・クラウドの CLI のログイン、マシンのグローバル設定（`~/.claude` のルールとスキル）は届かない。読めないことを回避しようとせず（鍵を作り直す・別の経路で取る）、クラウド環境の変数・ネットワークシークレットか、Claude のコネクタ（Slack・Gmail など）を使う。どちらも無ければ、止まった所と要る変数の名前をユーザーに伝える
- **道具はリポジトリが宣言した物だけ**。SessionStart hook（ai-rules の `templates/hooks/cloud-bootstrap.sh`）が mise と依存を入れる。hook が失敗を出したら、その手順を手で流して原因を見る。道具を足すときは手で入れて済ませず、`mise.toml` などの宣言に足す（次の会話でも同じに動くように）
- **ほかのリポジトリは、要るときにその会話へ付ける**。プロジェクトの設定に全部を登録せず、組織の台帳（一斉更新の対象一覧など）から要るリポジトリだけを付ける。付けられないときは、GitHub App が入っているかをユーザーに確かめてもらう
- 手元でしかできないこと（ブラウザでのログイン、端末のアプリ、社内ネットワーク）は、クラウドで粘らず、手元の会話か Remote Control に回すことをユーザーに 1 行で伝える
