# 選択票型と変更履歴ビュー（多数の指摘をさばく）

文書を通読して指摘が 5 件以上出たときの回し方。雛形は `assets/review-picker.html`（選択票）と `assets/redline.py`（変更履歴ビュー）。

## 全体の流れ（二段構え）

人が 1 件ずつ承認できるのは **30〜40 件が限度**。383 件を 10 件ずつ承認する方式は 3 週間で 4 ページしか進まなかった。一方、161 件をまとめて当てて変更履歴ビューで確認する方式は 1 回で見てもらえた。したがって:

1. **検証を通った指摘は先に当てる**。独立した 2 票（規則照合・改善判定）がともに「直す価値あり」と判定したものは、承認を待たずに適用して 1 コミットにする。git で 1 行単位に戻せるので、承認の順序を逆にしてよい
2. **変更履歴ビューで確認してもらう**。適用結果を `redline.py` で章ごとに見せ、気になる行だけ「戻す」かコメントを付けてもらう。既定が「採用」なので、ユーザーは拒否したい行にだけ触ればよい
3. **判断が要るものだけ選択票**。票が割れた指摘、行を足す・節を組み替える提案、本人しか知らない情報が要るものは、案A / 案B の形で 10 件ずつ

## 選択票型（review-picker.html）

`CONFIG` と `ITEMS` だけ書き換えれば動く。HTML を組み立てない。

- `opts` を書かない = 三択（修正する / 要検討 / スキップ）。`after` に修正後を書き、`rec` で既定を指定
- `opts` を書く = 案モード（案A / 案B / … / このままでよい）。押すとその案の文が編集欄に入り、ユーザーがそこを直せる
- `perPage` で 1 ページの件数（既定 10）。「このページの結果を出す」はそのページ分だけ出す。ページを移ると結果欄だけ空になり、編集欄と全体コメントは残る
- 文字列の中の `<a>…</a>` が足す部分、`<d>…</d>` が消す部分、`<f>…</f>` が動かさない行

一件に揃えるもの: 場所（行番号 + 節）、何が気になるか（理由を名指し）、現状、修正後、実測値。指摘は誤記・意味・日本語のねじれ・構成の 4 群に分けると判断が速い。既定値は自分の推奨にする（全件ニュートラルだと全部押させることになる）。

編集欄に何か書かれていたら、選ばれた案より**編集後の文を優先する**。編集ミス（語の重複、誤変換）が混ざることがあるので、適用前に読んで、直したら何を直したか報告する。

行を 2 つに分ける案は、ページ上でも実際に 2 つの `li` として描く。1 つの `li` の中で改行やダッシュで繋ぐと別物に見えて拒否される（`text` を配列にすればよい）。

## 変更履歴ビュー（redline.py）

```
python3 assets/redline.py <repo> <file> <before_ref> <out.html> [開始章] [###で章を割るH2名,…]
```

git の `before_ref` 時点と現在のファイルを行単位で突き合わせ、書き換えた行は文字単位の差分にする。左が変更前・右が変更後（1 列に重ねる表示にも切り替えられる）。削除は赤の取り消し線、追加は緑の下線。

- **章ごとに区切る**。`## ` 見出しごとにタブになる。第 6 引数に H2 名を渡すと、その配下だけ `### ` でさらに割る（案件詳細のように 1 つの H2 に大きな節が並ぶとき）。全文を一気に見せると集中力が切れる
- 行ごとに「戻す」とコメント。変更していない行にもコメントは付けられる
- 置き換えた行は、右列が変更後の並び順になるように出す。行数が同じ置き換えは位置で対応づけ、似ていない行は同じ位置に「削除 → 追加」で並べる。見出しと子行のように階層の違う行どうしは対応づけない

### 章ごとに送ってもらう

長い文書は、章ごとに回答を送ってもらい、こちらが反映している間にユーザーが次の章を見る流れにする。全章をまとめて待つより早く終わる。

- 章を見終えたら「この章の回答をコピー」。その章の印と「この章へのコメント」が出て、クリップボードに入る。押すと「次の章へ: …」のボタンが出る
- タブには、変更のある章ごとに状態が出る。**未回答**（触れていない）/ **入力中**（印はあるが送っていない）/ **送信済み** / **追加あり**（送った後に印やコメントを変えた）。直すところがない章も送れば「指摘なし」として送信済みになる。既定が「採用」なので、印がないだけでは「見て問題なかった」のか「見ていない」のかが分からないため
- 「全体へのコメント」は、次に送る回答に 1 回だけ付く。章ごとに送っても同じ話が繰り返し届かない
- 「送っていない章をまとめてコピー」は、送信済み以外の章をまとめて出す。触れていない章は「未回答（この章はまだ見ていない）」と書かれる
- 章を移ると回答欄は空になる。前の章の回答が残っていると貼り間違える
- 削る理由や書き直した理由は `--notes notes.json`（`{行の文字列: 理由}`）で行の下に出す。理由が見えないと、ユーザーは削ってよいかを判断できない

### 編集モード（--edit）: ユーザーがその場で直す

案を見て「戻す」かコメントするだけでなく、ユーザーが自分で文を直したいときは `--edit` を付ける。右の列（案）が、その場で書き換えられる欄になる。

- 左（元の文）と右（案）は同じ文字の大きさで、太字・リンク・コードを描いた見た目で並べる（`**` や `[]()` の記号は見せない。記号が並ぶと読みにくい）。右の欄は描いたまま書き換えられ（contenteditable）、送るときに Markdown へ戻す。太字の中に書き足した文字は太字のまま、リンクの URL は残る。日本語の変換中は描き直さず、確定してから差分を描く
- 右を書き換えるたびに、元の文との違いを色で出す（左の赤 = 消える部分、右の緑 = 足した部分）。案から直した行は欄の枠と行番号が黄色になる
- 行ごとに「元の文」（元に戻す）・「案」（案に戻す）・「コメント」。コメント欄は行の下に横いっぱいで開く（右の狭い列だと、書くほど文字が見えなくなる）。右の列はボタンだけの細い列にし、直していない行のボタンは薄く出す。章の見出し（`#` `##`）は編集の対象にしない
- **選択肢は、通らなかった行にだけ出す**。1 つの案が通らなかった行や、言い回しの好みが分かれる行は、`--alts alts.json`（`{案の行の文字列: [候補, …]}`）で候補を 3〜4 個、行の下に並べる。「使う」で右の欄を置き換え、⠿ をドラッグすると候補をまるごと、候補の文字を選んでドラッグすると一部だけを、落とした位置に入れられる（候補を組み合わせて直せる）。全部の行に選択肢を付けると読むのがつらいので付けない。候補ごとに何を前に出すか（意図・結果・短さ）が違うようにし、どれも 1 行に収まることを測ってから出す
- 送る内容は、案から直した行の `#行 [直した] 直した文`（行頭の `- ` や `####` を含めた 1 行）と `（案: …）`、コメント。「元の文」に戻した行は `[元の文に戻す]`、空にした行は `[削除]` と出る。受け手は直した文の 1 行で README の行を置き換えればよい
- 章のタブ・自動保存・章ごとの送信・`--done`・作り直しの扱いは、通常のモードと同じ

### 回答を受けてページを作り直す

途中の回答で案を直したくなったら、ページを作り直してよい。ただし**自動では読み込み直さない**（入力中の印が消えるのを嫌う）。

- 入力（戻す・行のコメント・章のコメント・送信済みの記録）はブラウザに自動で保存される。行は章・種類・文字列から作った ID で引き当てるので、作り直したページでも同じ行の印は残る
- 作り直すときは**同じ出力先に上書き**し、「更新した。区切りのよいところで画面上の『再読み込み』を押して」と伝える。`open` で開き直さない
- 回答を反映し終えた章は `--done "章名|章名"` に渡す。タブが「反映済み」になり、もう一度の回答を求めない
- 新しい案に差し替えた章は、前に送ったときと内容が変わるので、タブが「更新あり」になる。送ると「（更新した案への回答。前に送ったこの章の回答と置き換え）」と書かれる
- 「更新あり」と「反映済み」の章では、前の印とコメントを読み込まない。反映が済んだ意見が残ると、新しい案と混ざって読みにくいため。まだ送っていない章の入力中の内容は残る
- 保存機能のない古いページを開いているユーザーには、今の章を送り終えてから新しいページを開くよう伝える（古いページは読み込み直すと入力が消える）

回答はこの形で返ってくる:

```
[章: 案件詳細 › [No.11] …]
#136 [戻す] 案件収集 → AI 採点 → 本人 LINE への自動提案 → 回答まで、人手を介さない運用を実現
    → 「回答」だけだと弱い。「本人の回答」に
#213 設計した施策の実装からリリースまでを担当
    → ここに効果測定も入れたい
[この章へのコメント] 項目の並びを変えたい

（全 3 章のうち 1 章を送信済み。まだ: 強み / 技術スタック）
```

受け取ったときの扱い:

- **末尾の進み具合で、続きが来るかを判断する**。「まだ: …」があれば、残りの章を待たずにこの章の分を反映し、反映した内容だけを短く返す。「回答がそろいました」なら全体をまとめて確認する
- 見出しに「（再送。…置き換え）」「（更新した案への回答。…置き換え）」とある章は、前に受け取ったその章の回答を捨てて、こちらで置き換える
- 「未回答（この章はまだ見ていない）」があれば、その章を見てもらうよう伝える
- **ページは開き直さない**（入力中の印が消える）。ユーザーは今開いているページのタブで次の章に進める

## 一括適用の注意

- 適用は**後ろの行から**。行を増減する案があると前の行番号がずれる
- 案件名のように複数箇所（一覧行・summary・見出し）を揃える必要がある文字列は、同時に置換する
- 一括適用のあと、幅の検査・lint・ビルドを通す。副作用（折り返し、見出しの取り違え、階層のずれ）はここで出る。**同じ内容の行が重なっていないか**も見る（別々の指摘が同じ行を 2 通りに直して、1 行が 2 行に増えることがある）
- 先に当てた分の確認で「戻す」が付いた行は、次のコミットで戻す。理由がコメントにあれば、戻すのではなく直す

## 結果の受け取り方

`file://` ではクリップボード API が使えないことがあるので、テキストエリアに出して「全選択」も添える。
