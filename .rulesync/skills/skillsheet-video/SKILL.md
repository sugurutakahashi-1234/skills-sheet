# スキルシートの紹介動画

進め方（序盤・中盤・終盤）と、選択票・本番の上で見本を撮る道具・場面の並びの雛形・拍の測り方・公開の仕方は `motion-video` スキルにある。ここには、この題材だけの決めを置く。

再開するときは、まず `.tmp/videos/STATE.md`（現在地）と `.tmp/videos/opus-3/HANDOFF.md`（作り手への引き継ぎ書）を読む。

## 題材と事実

- 事実は README だけから取る。README に無い数字・社名・期間・成果は足さない
- 書かないもの: 約 1/3 削減・案件 1,000 件 × 1,000 名・5 分以内・3 サービス・マッチング 2 サイトの件数・CLI ツールの本数・PHP や Java の細部。案件（No.1〜11）は一覧（番号・案件名・客先・役割・始まりの年）だけを出し、取り組み・成果・技術の詳細は締めのリンクからスキルシートへ送る
- 「営業」を本人の役割として書かない（「営業支援」は可）。FDE の話に「完了」「納品」「受注」を使わない。顧客名は出さない
- 年: エンジニア歴は 2017 年〜（10 年目）。層の年は サーバーサイド 2017・iOS 2018・Flutter 2021・React Native（Expo）と Web 2025・インフラと AI と CTO 2026。サーバーサイドは本人の判断で 2017 年から（README の最初の案件 No.1 は 2018年9月〜）。Flutter は 2021（リードになった 2024 にはしない。案件の一覧で No.4〔2021年・Flutter エンジニア〕が Flutter の段に線で結ばれるので、段の年と合わせる）
- 強みは README の「強み」の 5 つの見出しをそのまま使う（略さない。長いものは 2 行）。README の強みを変えたら動画も合わせる
- 名前の読みは「たかはし すぐる」
- 案件で使った道具は、本人に「何をしたか」を聞いてから書く（例: BigQuery と Looker Studio は「既存の集計を見て判断した」で、自分でダッシュボードを作ったとは書かない）

## 本人が選んだ見た目と構成

- テーマカラー K1: 主役の黄 `#ffd23f`（上の文字は `#111318`）・差し色ピンク `#ff4f8b`（AI の色。上の文字は白）・文字 `#111318`・地 `#eceef1`・カテゴリ用 `#3a3f4b` `#3f6df6` `#10b98a` `#ff9f1c` `#8b5cf6`。背景は塗りつぶさず、枠と薄い塗りで見せる。今後の動画・スライドも、指定がなければこの色
- 構成（45 秒）: タイトル「45 秒でわかる 高橋 俊」（文字が中央で弾む）→「エンジニアとしての歩み」（下が支える階段に層が積まれ、縮んで柱になる。各段に年）→「これまでの案件」（柱の右に No.1〜11 を下から古い順に並べ、年ごとに束ねて左に年の目盛りを置き、層から線で結ぶ。本人「案件の話がないとよく分からない」）→「技術スタック」（柱の層から各行へ線）→「5 つの強み」（README の見出し＋ロゴ。支える層から線を引き、ほかの層を薄くする）→ 番号付きの一覧 → 締め「高橋 俊のスキルシートはこちら」（スキルシートの URL はピンクの札、GitHub と X は丸いロゴのボタン。締めの面が落ちて少し後に、URL の札の角に吹き出し「Web で公開中」が出る）。尺の配分は、強みの板 1 枚 約 2.2 秒（4 拍と 5 拍の交互で拍の頭に乗せる）・締め 約 4.3 秒（板が長いと待ちが長く、締めが長いと間延びする）
- 場面の切り替えは、見出しを載せた黄の帯が横切る形。歩み・案件・技術スタック・強みの 4 つとも帯で入る（1 か所だけ見出しの入れ替えにすると、切り替わったと気づかれない）。見出しは左上に読める大きさで残す
- 歩みの年は段の外（各層の左）に「2017年〜」の形で出し、柱になったら出さない。層の中には年の札を置かない。同じ年が続く段には出さない（薄く出すこともしない）。左上の年の数字（オドメーター）は残す
- フリーランスかどうかは動画に出さない（段は技術の分野で、2021 年の Flutter は会社員のときの案件なので、一緒に出すと Flutter からフリーランスになったように読める）
- ロゴは公式のカラー版を、札（白地・枠）に入れずに置く。縦は英字の見た目の中心にそろえる。横長・縦長のロゴ（AWS・Cloudflare・Claude Code・v0 など）は正方形の箱に押し込まず、面積をそろえて幅を変える（ロゴを出すすべての場面で）。本物のロゴが無い項目の代用（SwiftUI・UIKit に Swift、Riverpod に Flutter、Looker Studio に Looker）は本人の判断でそのまま付ける
- タイトルの下の行の黄の印は「株式会社ZENSHIN CTO」に付ける（読み手に最初に届けたい肩書き。年数は歩みの年の窓で伝わるので、「（2017年〜）」には付けない）
- 写真は `opus-3/assets/avatar.jpg`。タイトルでは角丸の四角、見出しと締めでは丸（ピンクの影）
- 尺はタイトルの数字（45 秒）と合わせる。タイトルの数字は `content.json` の `music.duration` から入るので、尺を変えるとタイトルも変わる（サムネ `opus-3/thumb/thumbnail.html` は手で直す）
- 使わない表現の一覧は `HANDOFF.md` の「使わない表現」にある（技術の札を 1 つずつ積む・切り抜きの枠・決め台詞・強みのカウントアップ・ロゴの無い項目・浮く層 など）

## 作業場所とファイル

- `.tmp/videos/`（コミットしない）: `STATE.md`（現在地）・`opus-3/`（採用した作品。`content.json` に中身、`HANDOFF.md` に引き継ぎ）・`versions/`（版の控え）・`mock*/`（仮アニメーションと選択票）・`bgm3/`（曲の候補）・`history.jsonl`（採った案と外した案）
- 文言・ロゴ・拍・場面の長さと並び（`scenes`）の直しは `opus-3/content.json` を書き換えるだけで済み、まとめ役がその場で入れる。曲の測った値は `opus-3/music.json`。書き換えたら `bunx -p typescript tsc -p .tmp/videos/opus-3/tsconfig.json && bun .tmp/videos/opus-3/check-content.ts` で形と参照を確かめる。見本は `bun .tmp/videos/opus-3/sample.ts <名前> --patch '<JSON>' --at <時刻>` で本番の上で撮る。新しい見た目や動きは、`HANDOFF.md` を渡した作り手に頼む
- サムネは `opus-3/thumb/thumbnail.png`（本人が選んだ「サムネ用に組んだ絵」。写真と「45 秒でわかる」「高橋 俊」を大きく）。Web 版の poster・README の動画の最初のコマ・OGP に使う
- 書き出した動画はデスクトップに `スキルシート動画_<案>_<段階>.mp4` で置く（作業ディレクトリの奥に置くだけにしない）
- ロゴはリポジトリの `assets/logos/`（技術名ごとの SVG、`logos.json` に表示名・分野・出どころ、`README.md` に代えのきまり）。足したら `opus-3/assets/logos-repo.js` を作り直す（手順は `HANDOFF.md`）
- 曲は Mixkit「What About Action?」の終わりの 46 秒を切り出したもの（原曲の 67.222 秒の小節の頭から。約 121 BPM・1 拍 0.4959 秒）を、44.65 秒で鳴り終わった後の 45 秒で止める。出どころとライセンスは `opus-3/assets/MUSIC.md`。HeyGen の曲は使わない（アカウントが無料プランで、非商用に限られる）

## 公開

- 公開している場所: Web 版は基本情報の上に幅 640px で置き、共有したときの絵はサムネの大きいカード。README は案内行の「45 秒の紹介動画つき」の下に、GitHub の添付の動画（最初の 1 コマをサムネにした版）を置く。動画を差し替えるときに合わせる 3 か所は、リポジトリのルール（`.rulesync/rules/main.md` の紹介動画の行）にある
- 差し替える前に、Mixkit のライセンスのページで Free License のままかを確かめ、画面を控える（曲の個別のページはサイトの検索に出ないので、ライセンスのページを控える。控えは `opus-3/publish/license/`）
- `motion-video` の「書き出す前の点検」（転換の途中・0 秒のコマ・スマホの幅・拍）を通す
- README を変えた後なら、動画の強みの見出しと技術の名前が README と食い違っていないか
